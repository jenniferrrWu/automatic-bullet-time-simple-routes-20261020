# CamCloneMaster 原生接口核查（2026-10-20）

结论：支持首帧图 + 动作内容视频 + 独立运镜参考视频同时输入。当前选中15例三路没有串线，但15例均使用项目自定义首 latent 采样固定，不能当成“未经采样修改的原生首帧能力”结论。旧结果保留；新增3例做纯原生基线。

| 条件 | 原生字段与实际语义 | 约束结论 |
|---|---|---|
| 首帧图 | `first_frame_path` 覆盖默认内容视频首帧；首时间 mask + VAE 通道，同时 CLIP 外观嵌入 | 原生首帧条件，不能保证输出像素、姿态或视角已通过 |
| 动作视频 | `content_video_path` → `content_latents` | 完整动作内容条件 |
| 运镜视频 | `ref_video_path` → `ref_latents` | 独立运镜条件；不能用动作视频误代 |
| 相机 JSON/数值角度 | 原生入口无被消费字段，pipeline `target_camera` 参数未被使用 | 无原生标定绝对30°控制 |
| 首尾帧 | 无 end_image/end_frame 等双端点入口 | CamClone 不支持原生双端点 Stage2 桥接 |


正文阅读范围：已读论文方法§3.1、§3.2（式3–5）与图2，以及§5.1的I2V首内容帧实验设置，并非只读摘要。§3.2/图2明确V_cam与V_cont两路VAE/token条件；原生代码ref_latents/content_latents对应这两路。I2V把内容tokens置零，代码也如此，不能用i2v模式冒充使用动作视频。论文使用内部I2V，公开Wan1.3B的精确首图消费和边界行为以first_frame_path覆盖、mask+VAE及CLIP代码为证，不能把论文示例画质或措辞推断成硬边界保证。

固定官方入口为81帧、832×480、50步、seed0、输出30fps；scheduler 的21 latent 截取写死。剩余12通用记录的 seed42 与实际 seed0 不符，应在新审计修正解释，保留旧记录原件。81源帧25fps→81输出帧30fps时播放快20%，不能说时长一致。完整定义后段若超过81帧不得静默截断；本轮须使用完整恰好81帧片段，否则标接口受限。

正向 Stage3 prompt 语义清晰。官方固定负向词含“静态/静止不动的画面”，可能与静止背景要求存在干扰；这不是已证实的失败原因。当前纯原生基线先保持官方负向不改；将来若修改需独立变体。端点重复视频同时携带人物/场景外观，必须标“零相对运镜代理”，不能称标定30°。

路线 A：真实 Stage2 原生末帧 + 完整源后段动作 + 独立静止运镜参考可以原生执行。实际输出f0与输入图另行测量、接缝另行人工验收，字段存在不等于约束有效。

路线 B：CamClone 单凭原内容首帧+静止参考不能设定绝对新视角。需外部新视角首图或其他原生新视角模型；仅prompt角度必须标未标定。CamClone 自身也没有首尾双端点接口，不能独立补B的 Stage2 桥接。不能据此或旧画质差淘汰模型。

新增完整后段复核：历史15例只有0/15输入覆盖原片t*至结尾；其他是有限动作窗口，不能按新要求称完整原片后段输入，逐例原片总帧/实际窗口已列JSON。

完整逐例路径、hash匹配、帧数、历史seed差异见同目录 `camclone_native_audit.json`。本次仅接口核查，未宣称视觉质量或完整拼接通过。
